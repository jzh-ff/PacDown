# PacDown 开发文档

> 面向二次开发与维护者 · v1.0 · 2026-08

## 1. 本地开发环境

```bash
git clone <repo> && cd pac
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python run.py                   # http://127.0.0.1:8300
```

可选：安装 ffmpeg（MP3 提取功能需要）、Node 无需（前端无构建）。

## 3. 关键机制

### 3.1 任务与历史合一
`videos` 表既是下载任务也是历史记录：`status` 即任务状态机
（pending → downloading → processing → done | failed）。
活动任务查询：`status IN ('pending','downloading','processing')`；
前端 1.5s 轮询 `/api/tasks`。

### 3.2 进度写库节流
progress hook 每块回调，直接写库会打爆 SQLite。`downloader._run` 中
`last["t"]` 节流 0.4s；yt-dlp 路径 `_percent_str/_speed_str`，直链路径按
字节数计算。

### 3.3 线程安全
- SQLite：单连接 `check_same_thread=False` + 全局 `threading.Lock`（execute/query 内部加锁）
- 配置：`config.py` 读写均持锁
- worker 线程通过数据库轮询 + Event 唤醒取任务（`_wake.set()`）

### 3.4 Cookie 流转
- 配置存 `config.json`（明文本地）
- yt-dlp 用法：`_cookie_file()` 生成 Netscape 格式临时文件，用完删除
- httpx 用法：直接塞 `Cookie` 请求头
- API 回显打码：`__SET__`（已配置）/ 前端提交 `__KEEP__`（保持不变）

### 3.5 封面防盗链
平台封面 URL 有 Referer 校验。前端 `<img>` 一律走
`/api/cover?url=...&platform=...` 代理，后端按平台附加 Referer 拉取。

## 4. 新增平台解析器（贡献指南）

1. 新建 `app/parsers/yourplatform.py`：

```python
from . import http_download as hd
from .base import ParseError, Parser, VideoInfo, register

@register
class YourParser(Parser):
    platform = "yourplatform"
    display_name = "平台名"

    def can_parse(self, url): 
        return "yourplatform.com" in url.lower()

    def parse(self, url) -> VideoInfo:
        # 解析元数据，失败 raise ParseError("人话错误信息")
        return VideoInfo(platform=self.platform, ...)

    def download(self, info, dest_dir, options, progress, filename_prefix=""):
        # progress(0~100, "速度描述")；返回 {file_path, file_size, images?}
        return hd.stream_download(direct_url, dest, "yourplatform", progress, referer=...)
```

2. `app/parsers/__init__.py`：import 注册 + `PLATFORM_META` 加名称与品牌色
3. `app/parsers/base.py`：`KNOWN_HOSTS` 加域名（用于链接识别提示）
4. 前端 `app.js`：`PLATFORM_NAME` 加显示名；`index.html` 历史筛选加 option
5. CSS 徽章色：`design.css` 加 `.badge-yourplatform`

解析失败信息要面向用户（说明原因和补救办法），模块间互不影响。

## 5. 调试技巧

```bash
# 单测某个解析器
python -c "
from app.parsers import dispatch
info = dispatch('https://...').parse('https://...')
print(info.title, info.cover_url, info.raw.get('direct_url'))"

# 看 worker 实时日志（任务表）
curl -s http://127.0.0.1:8300/api/tasks | python -m json.tool

# 直接查库
sqlite3 data/metadata.db "SELECT id,status,progress,title,error FROM videos ORDER BY id DESC LIMIT 5"

# UI 回归截图（Playwright）
# 参考 docs/screenshots 的生成方式，四页 + 明暗主题
```

常见坑：
- **平台接口又变了**：优先在该平台 parser 内修，勿动公共层；错误消息测试给用户看
- **yt-dlp 解析挂了**：`pip install -U yt-dlp` 通常能修（B站/YouTube 变化它更新最快）
- **412/风控**：降低请求频率；引导配置 Cookie；B站空间有 wbi+yt-dlp 双路径自动回退
- **Windows 控制台中文乱码**：`chcp 65001`

- [ ] B站公开视频解析+下载通过
- [ ] 抖音（配置 Cookie）解析通过
- [ ] 历史统计数字正确、CSV 导出打开不乱码
- [ ] 明暗主题切换正常、封面代理可用
- [ ] ffmpeg 缺失时 MP3 选项给出明确报错

## 7. 已知限制

| 限制 | 原因 | 计划 |
|---|---|---|
| 抖音免 Cookie 解析不可用 | 平台 2025 年关闭公开通道 | Cookie 路径已实现；后续跟进社区新通道 |
| 小红书解析依赖 Cookie | 强风控 | 保持解析器隔离，接口恢复即可用 |
| B站番剧/课程部分需要会员 | 权限限制 | 配置会员 Cookie 可解 |
| 订阅抖音博主成功率一般 | 主页风控 | 建议 Cookie；错误已在卡片展示 |
