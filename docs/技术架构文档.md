# PacDown 技术架构文档

> 全平台视频下载工具 · v1.0 · 2026-08

## 1. 系统概览

PacDown 是一个本地运行的 Web 应用：粘贴视频链接 → 自动识别平台 → 解析无水印源 → 队列下载 → 元数据双份保存，支持订阅博主自动追更。

```
┌────────────────────────────────────────────────────┐
│  浏览器（static/ 单页应用）                          │
│  下载页 · 历史页 · 订阅页 · 设置页（明暗双主题）      │
└──────────────┬─────────────────────────────────────┘
               │ HTTP / JSON（轮询进度）
┌──────────────▼─────────────────────────────────────┐
│  FastAPI (app/main.py)                              │
│  parse / download / tasks / history / config / subs │
├────────────────────────────────────────────────────┤
│  DownloadManager (downloader.py)                    │
│  线程池 worker × N → 进度回调 → 后处理 → 落盘        │
├───────────────┬────────────────┬───────────────────┤
│ Parsers 插件层 │ postprocess    │ scheduler         │
│ (app/parsers) │ MP3/弹幕       │ APScheduler 订阅  │
├───────────────┴────────────────┴───────────────────┤
│  SQLite (data/metadata.db)  ·  config.json          │
└────────────────────────────────────────────────────┘
```

## 2. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Python 3.10+ / FastAPI / uvicorn | 单进程 + 线程池并发下载 |
| 通用引擎 | yt-dlp | B站解析下载 + 上千站点兜底 |
| HTTP 客户端 | httpx | 平台直连解析（支持 http2、代理） |
| 定时任务 | APScheduler | 订阅追更（默认 30 分钟） |
| 前端 | 原生 HTML/CSS/JS | 无构建、离线可用；CSS 变量双主题 |
| 存储 | SQLite + JSON sidecar | 数据库查询 + 文件级迁移各取所长 |
| 音频/弹幕 | ffmpeg / B站弹幕 API | MP3 提取、XML 弹幕 |

## 3. 模块设计

### 3.1 解析器插件（app/parsers/）

所有解析器继承 `Parser` 基类，通过 `@register` 装饰器注册到注册表。`dispatch(url)` 按 `can_parse()` 匹配；都不命中则回落 `generic`（yt-dlp 引擎）。

**统一数据模型 `VideoInfo`**：platform、video_id、title、author、cover、duration、publish_time、stats、quality_options、images（图集）、raw（原始数据，写入 sidecar）。

| 文件 | 平台 | 解析路径 |
|---|---|---|
| bilibili.py | B站 | yt-dlp `extract_info` 解析 + 下载；网页 view API 补充数据；弹幕 cid |
| douyin.py | 抖音 | **双路径**：① 用户 Cookie + PC SSR 数据流提取 playAddr ② iesdouyin 分享页 `_ROUTER_DATA`（免配置，视风控状态可用性浮动） |
| kuaishou.py | 快手 | 短链重定向 → 页面 `__NEXT_DATA__`/videoData 挖掘 photo.mainMvUrls |
| xiaohongshu.py | 小红书 | note 页 `__INITIAL_STATE__` 提取视频流/图集（通常需 Cookie） |
| generic.py | 通用 | yt-dlp 引擎（YouTube、西瓜、微博等上千站点） |
| ytdlp_engine.py | — | yt-dlp 封装：cookie 文件生成、进度 hook、清晰度列表、失败回退 best |
| http_download.py | — | httpx 流式下载、短链重定向、HTML 内嵌 JSON 提取、防盗链 Referer 表 |

**去水印原理**：抖音/快手解析的是平台无水印源地址（playAddr / mainMvUrls），下载即无水印，非 AI 消除。B站视频本身无水印。

### 3.2 下载管道（app/downloader.py）

一条 `videos` 记录即一个任务（任务与历史同源）：

```
create_task: parse → 去重检查(video_id) → INSERT(pending)
worker × N:  SELECT pending → downloading(进度节流写库 0.4s)
             → parser.download() → processing
             → 封面下载 → [弹幕] → [MP3] → sidecar JSON
             → done(downloaded_at)
失败:        status=failed + error，可 retry 重置回 pending
```

- 目录规则：`下载目录/平台/作者/日期_标题.{mp4,jpg,xml,json}`
- 图集：逐张下载 `{标题}_{序号}.jpg`
- 文件名冲突由 yt-dlp/系统处理；非法字符统一 `safe_filename` 清洗

### 3.3 订阅调度（app/scheduler.py）

- B站空间列表：**wbi 签名直调 arc/search API**，失败（412 风控）自动回退 **yt-dlp flat playlist**
- 抖音博主：主页 `_ROUTER_DATA` 挖掘 aweme 列表（需 Cookie，尽力而为）
- 比对库里 video_id，新视频自动入下载队列；间隔可配（默认 30 分钟）
- 失败写入 `last_error` 并在订阅卡片展示

### 3.4 数据模型

**videos**（任务+历史合一）：platform / video_id / title / author / cover / duration / publish_time / stats(JSON) / quality / file_path / file_size / audio_path / danmaku_path / images(JSON) / raw_json / status / progress / speed / error / options(JSON) / created_at / downloaded_at

**subscriptions**：platform / uploader_id / uploader_name / avatar / enabled / last_checked / last_error / new_count

**Sidecar JSON**：与视频同目录，含全部元数据 + raw 原始数据，脱离数据库可迁移。

### 3.5 API 一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/parse | 批量解析预览（不入库） |

| GET | /api/tasks | 活动任务与实时进度 |

| GET | /api/cover | 封面代理（带 Referer 绕防盗链） |

| GET/POST | /api/config/dirs | 下载目录查看/切换 |
| GET/POST/PATCH/DELETE | /api/subscriptions… | 订阅 CRUD + 手动检查 |

### 3.6 前端

- 单页应用：`index.html` + `css/design.css` + `js/app.js`，无构建、无外部 CDN（离线可用）
- 设计系统：CSS 变量双主题（暗色默认）、紫→蓝渐变、玻璃拟态（backdrop-filter）、等宽数字数据展示
- 签名元素：下载进度条流动光带（shimmer/slide 动画）
- 状态徽章呼吸灯、骨架屏、空状态、Toast、键盘 Esc 关闭、focus-visible、prefers-reduced-motion
- 进度获取：1.5s 轮询 /api/tasks（本地场景足够，无 SSE 复杂度）

## 4. 风控与对策（重要）

平台风控持续收紧，本工具的对策分层：

| 风险 | 对策 |
|---|---|
| 抖音公开通道关闭（2025+） | Cookie 路径为主 + 免 cookie 兜底 + 失败时 UI 给出 Cookie 配置指引 |
| 小红书强风控 | 解析器隔离，Cookie 可配，错误信息明确 |
| B站空间 API 412 | wbi 签名 + yt-dlp 双路径 |
| 任意平台接口变化 | 解析器单文件隔离，改动不影响其他平台 |
| 高清限制 | B站 1080P+ 需 SESSDATA；清晰度请求失败自动回退 best |

## 5. 安全与合规

- 仅监听 127.0.0.1（Docker 模式 0.0.0.0 由用户自行暴露）
- Cookie 只存本机 config.json，API 回显打码（`__SET__`/`__KEEP__` 占位）
- 仅供个人学习与备份已授权内容，请勿用于批量爬取与分发
