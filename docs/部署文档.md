# PacDown 部署文档

> 把项目打包并部署到自己的服务器（Linux / NAS）· v1.1

## 0. 一键脚本部署（推荐，与 AIword 同模式）

项目自带「本机打包 → scp 上传 → 服务器切换 + 自动回滚」一键发布链路，支持 Docker / PM2 两种模式：

```bash
# Git Bash / macOS / Linux（默认 Docker 模式）
./scripts/deploy-local.sh            # = ./scripts/deploy-local.sh docker
./scripts/deploy-local.sh pm2        # PM2 裸机模式

# Windows PowerShell
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1           # Docker 模式
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1 pm2       # PM2 模式
```

默认目标：`root@82.156.224.145:/www/wwwroot/pacdown`（用环境变量覆盖：`DEPLOY_HOST=... DEPLOY_DIR=...`）。

### Docker 模式（默认）

- 本机：`git archive` 打包已跟踪源码（Python 无需构建，包即源码）→ scp → ssh 触发 `deploy-docker.sh`
- 服务器 `deploy-docker.sh`：解包到应用目录 → 备份当前镜像为 `pacdown:backup` → `docker compose build`（自动注入国内加速：腾讯云内网 apt 镜像 + 清华 PyPI，可用 `APT_MIRROR`/`PIP_INDEX_URL` 环境变量覆盖）→ `docker compose up -d` → 健康检查 `/api/platforms`，失败自动把 backup 镜像换回并重启
- 手动回滚：`docker tag pacdown:backup pacdown:latest && docker compose up -d`
- 数据持久化：`/www/wwwroot/pacdown/{downloads,data,config}` 挂载进容器，重建容器不丢数据

**服务器一次性准备**（仅首次）：
```bash
# 1. 装 Docker（含 compose 插件；国内用阿里云镜像脚本）
curl -fsSL https://get.docker.com | bash -s docker --mirror Aliyun
usermod -aG docker $USER     # 免 sudo，重新登录生效（root 可跳过）

# 2. 配置 Docker Hub 镜像加速（腾讯云服务器用内网地址，仅腾讯云内有效）
cat > /etc/docker/daemon.json <<EOF
{"registry-mirrors": ["https://mirror.ccs.tencentyun.com"]}
EOF
systemctl restart docker
```

### PM2 裸机模式

- 服务器 `deploy.sh`：解压到 `releases/<时间戳>` → requirements.txt md5 比对（变了才 pip install）→ `current` 软链原子切换 → PM2 重启 → 健康检查，失败自动回滚软链
- 手动回滚：`ln -sfn releases/<旧版本> /www/wwwroot/pacdown/current && pm2 restart pacdown`
- 服务器需预装：`apt install -y python3 python3-venv ffmpeg` 与 PM2（`npm i -g pm2`）

**服务器目录结构**（数据与代码分离，升级/回滚不动数据）：
```
/www/wwwroot/pacdown/
├── pacdown.tgz                   # 本机上传的运行包（用完即删）
├── app/ static/ run.py …         # 代码（Docker 模式的构建上下文）
├── downloads/ data/ config/      # 持久数据（Docker 挂载；PM2 模式在 shared/）
├── shared/                       # PM2 模式：config.json/downloads/data
├── releases/  current -> …       # PM2 模式：历史版本与当前软链
└── deploy.sh / deploy-docker.sh  # 服务器端发布脚本（包内自带）
```

下面的方案 A/B 是手动版流程，供理解细节或部署到其他环境时使用。

## 1. 打包（本机执行一次）

在项目根目录执行（只打包 git 已跟踪的文件，自动排除 config.json、downloads/、data/ 等运行时数据）：

```bash
git archive --format=tar.gz --prefix=pacdown/ -o dist/pacdown-v1.1.tar.gz HEAD
```

产物：`dist/pacdown-v1.1.tar.gz`（约 7MB，含 Dockerfile 与全部源码文档）。

## 2. 上传到服务器

```bash
# Windows PowerShell / Git Bash 均可（OpenSSH 自带 scp）
scp dist/pacdown-v1.1.tar.gz 用户名@服务器IP:/opt/

# 示例：scp dist/pacdown-v1.1.tar.gz root@192.168.1.10:/opt/
```

## 3. 方案 A：Docker 部署（手动版）

服务器只需装了 Docker 与 docker compose 插件，无需配置 Python 环境：

```bash
ssh 用户名@服务器IP
mkdir -p /opt/pacdown && tar -xzf /opt/pacdown-v1.1.tar.gz -C /opt --strip-components=0
cd /opt/pacdown/pacdown
# 国内服务器构建加速（可选）：腾讯云内网 apt 镜像 + 清华 PyPI
APT_MIRROR=mirrors.cloud.tencent.com \
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple \
docker compose up -d --build
```

完成后访问 `http://服务器IP:8300`。

- 镜像内置 ffmpeg，视频工具开箱即用
- 数据持久化在宿主机 `./downloads`、`./data`、`./config`（删容器不丢数据）
- 后续升级：重新打包上传 → 解压覆盖 → `docker compose up -d --build`

**迁移本机配置（可选）**：把本机 `config.json` 复制到服务器的 `/opt/pacdown/pacdown/config/config.json`（注意是挂载目录），重启容器即可复用 Cookie 与设置：

```bash
scp config.json 用户名@服务器IP:/opt/pacdown/pacdown/config/config.json
docker compose restart
```

## 4. 方案 B：裸机 Python 部署（无 Docker）

适合已有 Python 3.10+ 的服务器：

```bash
cd /opt/pacdown/pacdown
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt          # 国内服务器可加 -i https://pypi.tuna.tsinghua.edu.cn/simple
apt install -y ffmpeg                    # 视频工具需要（Debian/Ubuntu；CentOS 用 yum/dnf）

# 后台运行（监听所有网卡）
PACDOWN_HOST=0.0.0.0 nohup python run.py > pacdown.log 2>&1 &
```

### systemd 守护（推荐，开机自启 + 崩溃重启）

新建 `/etc/systemd/system/pacdown.service`：

```ini
[Unit]
Description=PacDown 视频下载工具
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/pacdown/pacdown
Environment=PACDOWN_HOST=0.0.0.0
ExecStart=/opt/pacdown/pacdown/.venv/bin/python run.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now pacdown
systemctl status pacdown     # 查看状态
journalctl -u pacdown -f     # 看日志
```

## 5. 部署后检查

1. 防火墙/安全组放行 **8300** 端口（云服务器在控制台安全组加规则）
2. 浏览器访问 `http://服务器IP:8300`，首页正常加载
3. 「设置」页检查下载目录（Docker 版默认 `/app/downloads`，即宿主机 `./downloads`）
4. 试下一条 B站链接 + 工具箱截帧任务，确认下载与 ffmpeg 正常

## 6. 常见问题

**Q：服务器在国内，docker build 拉镜像/pip 很慢？**
配置 Docker Hub 镜像加速（见第 0 节 daemon.json；腾讯云用 `mirror.ccs.tencentyun.com`，其他用 DaoCloud/阿里云加速器）。构建时的 apt 与 pip 已通过 `APT_MIRROR` / `PIP_INDEX_URL` 构建参数自动走国内镜像（一键脚本默认注入）。

**Q：想从外网访问？**
建议套一层反向代理（Nginx/Caddy）并开启 HTTPS 与 Basic Auth，不要把 8300 直接暴露公网——本应用无登录鉴权，仅监听 127.0.0.1 的设计就是安全边界。

**Q：数据库和本机想合并？**
直接把本机 `data/metadata.db` 与 `downloads/` 整个目录 scp 到服务器对应位置即可，sidecar JSON 与数据库天然可迁移。

**Q：如何更新版本？**
一键脚本直接重跑即可（Docker 模式镜像备份回滚，PM2 模式保留最近 3 个版本）；手动方式：`git archive` 重新打包 → scp → 解压覆盖 → 重启（Docker 重新 build，systemd 则 `systemctl restart pacdown`）。数据库会自动 `_migrate` 平滑升级。
