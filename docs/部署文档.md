# PacDown 部署文档

> 把项目打包并部署到自己的服务器（Linux / NAS）· v1.1

## 0. 一键脚本部署（推荐，与 AIword 同模式）

项目自带与 AIword 相同的「本机打包 → scp 上传 → 服务器原子切换 + 自动回滚」一键发布链路：

```bash
# Git Bash / macOS / Linux
./scripts/deploy-local.sh

# Windows PowerShell
powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1
```

默认目标：`root@82.156.224.145:/www/wwwroot/pacdown`（用环境变量覆盖：`DEPLOY_HOST=... DEPLOY_DIR=...`）。

**链路说明**：
- 本机：`git archive` 打包已跟踪源码（Python 无需构建，包即源码）→ scp 上传 → ssh 触发服务器 `deploy.sh`
- 服务器 `deploy.sh`：解压到 `releases/<时间戳>` → requirements.txt md5 比对（变了才 pip install，默认清华源）→ `current` 软链原子切换 → PM2 重启 → 健康检查 `/api/platforms`，失败自动回滚软链
- 手动回滚：`ln -sfn releases/<旧版本> /www/wwwroot/pacdown/current && pm2 restart pacdown`

**服务器目录结构**（数据与代码分离，升级/回滚不动数据）：
```
/www/wwwroot/pacdown/
├── current -> releases/<时间戳>   # 当前版本软链
├── releases/                     # 历史版本（保留最近 3 个）
├── shared/
│   ├── config.json               # 持久配置（Cookie，PACDOWN_CONFIG_DIR 指向这里）
│   ├── downloads/                # 下载的视频
│   └── data/                     # SQLite 数据库
├── .venv/                        # Python 虚拟环境
└── ecosystem.config.js           # PM2 配置（deploy.sh 自动生成）
```

**服务器一次性准备**（仅首次）：
```bash
apt install -y python3 python3-venv ffmpeg   # Python 3.10+ 与 ffmpeg
curl -fsSL https://get.docker.com | bash      # 不用 Docker 可跳过
npm i -g pm2                                  # 进程守护（AIword 服务器已装则跳过）
```

下面的方案 A/B 是手动版流程，供理解细节或部署到其他环境时使用。

## 1. 打包（本机执行一次）

在项目根目录执行（只打包 git 已跟踪的文件，自动排除 config.json、downloads/、data/ 等运行时数据）：

```bash
git archive --format=tar.gz --prefix=pacdown/ -o dist/pacdown-v1.1.tar.gz HEAD
```

产物：`dist/pacdown-v1.1.tar.gz`（约 7MB，含 Dockerfile 与全部源码文档）。

## 2. 上传到服务器

```bash
# Windows PowerShell / Git Bash 均可（OpenSSH 自带 scp）
scp dist/pacdown-v1.1.tar.gz 用户名@服务器IP:/opt/

# 示例：scp dist/pacdown-v1.1.tar.gz root@192.168.1.10:/opt/
```

## 3. 方案 A：Docker 部署

服务器只需装了 Docker 与 docker compose 插件，无需配置 Python 环境：

```bash
ssh 用户名@服务器IP
mkdir -p /opt/pacdown && tar -xzf /opt/pacdown-v1.1.tar.gz -C /opt --strip-components=0
cd /opt/pacdown/pacdown
docker compose up -d --build
```

完成后访问 `http://服务器IP:8300`。

- 镜像内置 ffmpeg，视频工具开箱即用
- 数据持久化在宿主机 `./downloads`、`./data`、`./config`（删容器不丢数据）
- 后续升级：重新打包上传 → 解压覆盖 → `docker compose up -d --build`

**迁移本机配置（可选）**：把本机 `config.json` 复制到服务器的 `/opt/pacdown/pacdown/config/config.json`（注意是挂载目录），重启容器即可复用 Cookie 与设置：

```bash
scp config.json 用户名@服务器IP:/opt/pacdown/pacdown/config/config.json
docker compose restart
```

## 4. 方案 B：裸机 Python 部署（无 Docker）

适合已有 Python 3.10+ 的服务器：

```bash
cd /opt/pacdown/pacdown
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt          # 国内服务器可加 -i https://pypi.tuna.tsinghua.edu.cn/simple
apt install -y ffmpeg                    # 视频工具需要（Debian/Ubuntu；CentOS 用 yum/dnf）

# 后台运行（监听所有网卡）
PACDOWN_HOST=0.0.0.0 nohup python run.py > pacdown.log 2>&1 &
```

### systemd 守护（推荐，开机自启 + 崩溃重启）

新建 `/etc/systemd/system/pacdown.service`：

```ini
[Unit]
Description=PacDown 视频下载工具
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/pacdown/pacdown
Environment=PACDOWN_HOST=0.0.0.0
ExecStart=/opt/pacdown/pacdown/.venv/bin/python run.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now pacdown
systemctl status pacdown     # 查看状态
journalctl -u pacdown -f     # 看日志
```

## 5. 部署后检查

1. 防火墙/安全组放行 **8300** 端口（云服务器在控制台安全组加规则）
2. 浏览器访问 `http://服务器IP:8300`，首页正常加载
3. 「设置」页检查下载目录（Docker 版默认 `/app/downloads`，即宿主机 `./downloads`）
4. 试下一条 B站链接 + 工具箱截帧任务，确认下载与 ffmpeg 正常

## 6. 常见问题

**Q：服务器在国内，docker build 拉镜像/pip 很慢？**
给 Docker 配镜像加速器（`/etc/docker/daemon.json` 的 `registry-mirrors`），pip 用清华源 `-i https://pypi.tuna.tsinghua.edu.cn/simple`（一键脚本已默认清华源，可用 `PIP_INDEX_URL` 环境变量覆盖）。

**Q：想从外网访问？**
建议套一层反向代理（Nginx/Caddy）并开启 HTTPS 与 Basic Auth，不要把 8300 直接暴露公网——本应用无登录鉴权，仅监听 127.0.0.1 的设计就是安全边界。

**Q：数据库和本机想合并？**
直接把本机 `data/metadata.db` 与 `downloads/` 整个目录 scp 到服务器对应位置即可，sidecar JSON 与数据库天然可迁移。

**Q：如何更新版本？**
一键脚本直接重跑即可（自动保留最近 3 个版本可回滚）；手动方式：`git archive` 重新打包 → scp → 解压覆盖 → 重启（Docker 重新 build，systemd 则 `systemctl restart pacdown`）。数据库会自动 `_migrate` 平滑升级。
